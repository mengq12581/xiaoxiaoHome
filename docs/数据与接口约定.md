# 数据与接口约定

约定优先于实现：执行者可以换框架、换引擎，但这一节描述的字段、路径、错误行为不许改；要改先写进 `docs/验收问题.md` 并问客户。

## 1. 状态对象（唯一的状态载体）

```json
{
  "activity": "write_notes",
  "source": "task:daydream",
  "since": "2026-11-11T10:10:00+08:00",
  "min_dwell": 90,
  "meta": { "note": "神游定时任务", "priority": "normal" }
}
```

规则：

- `activity`：必填，必须存在于 `config/activities.json` 的 `activities` 里；否则拒绝。
- `source`：必填，`task:<名字>` / `sim:click` / `idle` / `manual` 四类前缀，未识别前缀按 `manual` 处理并记警告。
- `since`：必填，ISO8601 带时区；缺失时服务端补当前时间，不算错误。
- `min_dwell`：可选，秒，整数 0–1800；默认取活动配置里的值。
- `meta`：可选对象，最大 1KB，原样透传给前端做调试展示。
- 未知字段：忽略但不报错（向前兼容）。

## 2. 双通道

### 2.1 文件通道 `state.json`

- 路径：仓库根 `runtime/state.json`（运行时目录，不提交到 git；`runtime/` 进 `.gitignore`）。
- 前端每 1 秒读取一次（可用文件监听替代），读到 `since` 变化即视为新状态。
- 文件不存在或 JSON 非法时，前端保持上一次有效状态，控制台打警告，不崩溃。

### 2.2 本地 HTTP 接口

- 只监听 `127.0.0.1`，默认端口 `4317`（可配置，冲突时自动 +1 并打印实际端口）。
- `POST /state`：请求体同状态对象，成功返回 200 与当前状态。
- `GET /state`：返回当前状态 + `received_at`。
- `GET /history?limit=50`：返回最近状态变更。
- `GET /activities`：返回可用活动列表与字段说明。
- `POST /state` 携带非法 `activity`：返回 400，体为 `{"error":"unknown_activity","allowed":[...]}`。
- 请求体超过 8KB 返回 413。
- 写入成功后，服务端同时更新 `runtime/state.json` 并追加 `runtime/state-history.jsonl`。

### 2.3 冲突处理

两个写入方（模拟器、任务脚本）同时写：以最后到达者为准，`state-history.jsonl` 两条都记，前端取最新 `since`。不做锁，不做合并。

## 3. 历史日志 `runtime/state-history.jsonl`

每行一条：

```json
{"ts":"2026-11-11T10:10:03+08:00","activity":"write_notes","source":"task:daydream","min_dwell":90,"prev":"watch_tv","prev_duration":143}
```

- `prev_duration`：上一个活动实际持续秒数，用于验收「她演得比任务长」。
- 单文件超过 5MB 自动轮转成 `state-history.1.jsonl`，最多保留 3 个。

## 4. 场景配置

### 4.1 `config/rooms.json`

```json
{
  "grid": { "size": 0.5, "unit": "m" },
  "rooms": [
    {
      "id": "living",
      "name": "客厅",
      "bounds": [[0, 0], [6, 4.5]],
      "floor": "wood_light",
      "walls": [
        { "id": "living_top", "from": [0, 4.5], "to": [6, 4.5], "height": 2.6, "windows": [[1.2, 3.2]] }
      ],
      "doors": [ { "id": "door_to_bedroom", "wall": "living_right", "at": [6, 2.2], "width": 1.0 } ]
    },
    {
      "id": "bedroom",
      "name": "卧室",
      "bounds": [[6, 0], [9.5, 4.5]],
      "floor": "wood_warm",
      "walls": [],
      "doors": []
    }
  ],
  "nav": { "nodes": [[0.5, 0.5], [3, 1], [5.5, 2], [7, 1.5]], "edges": [[0, 1], [1, 2], [2, 3]] }
}
```

- 加一个房间 = 加一个对象 + 在 `nav` 里加节点与边；场景必须真的出现新房间。
- `nav` 允许由执行者改成自动生成（网格寻路），但 `nav` 字段必须保留，手工节点优先。

### 4.1b `config/camera.json`（相机与墙体遮挡参数）

```json
{
  "target": [4.7, 0, 2.2],
  "minPolarDeg": 25,
  "maxPolarDeg": 70,
  "minDistance": 4.5,
  "maxDistance": 16,
  "startAzimuthDeg": 225,
  "startPolarDeg": 55,
  "startDistance": 12,
  "wallFadeOpacity": 0.08,
  "wallFadeWithOutline": true,
  "wallFadeTarget": "character_or_room_center"
}
```

- 自由环绕、连续缩放；`minDistance` 到 `maxDistance` 之间连续插值，不分档。
- `wallFadeTarget`：射线检测的落点，默认朝角色，找不到角色时朝房间中心。
- 墙体必须是可单独控透明的独立 mesh；地板、家具、门窗不参与透明。

### 4.2 `config/furniture.json`

```json
{
  "items": [
    {
      "id": "sofa",
      "kind": "sofa",
      "room": "living",
      "position": [1.2, 2.4],
      "rotation": 90,
      "size": [2.1, 0.9, 0.75],
      "draggable": true,
      "anchors": [
        { "id": "sofa_seat", "local": [0, 0.45, 0.1], "facing": "forward", "activity": "watch_tv" }
      ],
      "group": null
    },
    {
      "id": "desk",
      "kind": "desk",
      "room": "living",
      "position": [5.4, 2.2],
      "rotation": 180,
      "size": [1.4, 0.7, 0.75],
      "draggable": true,
      "anchors": [
        { "id": "desk_seat", "local": [0, -0.35, 0.55], "facing": "toward", "activity": "use_computer" }
      ],
      "group": "desk_set"
    }
  ]
}
```

- `anchors[].local` 是相对家具原点的局部坐标（米），随家具移动旋转一起变换。
- `group` 相同的家具联动：拖动电脑桌，椅子一起走。
- `draggable: false` 用于墙体、窗、门这类不许动的东西。

### 4.3 `config/activities.json`

```json
{
  "activities": {
    "write_notes": {
      "anim": "sit_write",
      "anchor": "desk_seat",
      "min_dwell": 90,
      "weight": 0,
      "duration": [60, 240],
      "face": "anchor_forward",
      "props": ["notebook_open"]
    }
  },
  "quiet_hours": ["23:30", "07:30"],
  "idle_after_sec": 120,
  "idle_pool_override": {
    "quiet": { "sleep": 60, "daydream_window": 25, "wander": 15 }
  }
}
```

- `props`：动作需要的道具（翻开本子、戴耳机、盖被），道具是家具的子物体或角色挂点。

### 4.4 `config/characters.json`（扩展性预留）

```json
{
  "active": "xiaoxiao",
  "characters": [
    {
      "id": "xiaoxiao",
      "name": "笑笑",
      "height": 1.55,
      "model": "assets/xiaoxiao_q_turnaround.jpg",
      "model_type": "procedural_or_gltf",
      "palette": { "hair": "#1b1b1f", "top": "#f4efe6", "pants": "#9aa0a6", "skin": "#f7e6da" },
      "activities": "all"
    }
  ]
}
```

- v0.1 只允许一个角色；第二个条目（帅帅）允许存在但 `active` 切过去时用占位小人显示，不报错，不要求有真实形象。
- 导演层接口必须按「多角色」写：`director.setState(characterId, state)`，v0.1 内部只路由给 `active`。

## 5. 布局持久化

- 拖动后写 `localStorage["xiaoxiao-home.layout"]`，结构 = 全量 `furniture.items` 的位置与旋转。
- 清理缓存后回落到 `config/furniture.json` 默认值。
- 右上角提供「导出布局 JSON / 恢复默认」两个按钮，导出文件放 `runtime/layout-<时间戳>.json`。

## 6. 错误与日志

- 前端日志：`logs/frontend-YYYYMMDD.log`，含状态接收、寻路失败、配置校验失败。
- 服务端日志：`logs/state-server-YYYYMMDD.log`。
- 配置校验失败必须在启动时直接报错并指出文件与字段，不许静默用默认值兜底。
- 寻路失败时角色停在原地并打警告，不许穿墙。
