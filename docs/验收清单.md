# 验收清单

用法：每个里程碑结束按对应分组逐条打勾；不能跳着验。打不了勾的写进 `docs/验收问题.md`（现象、复现步骤、期望），修完再验。

标记：`[ ]` 未验 / `[x]` 通过 / `[!]` 不通过 / `[-]` 不适用

## 0. 启动与工程

- [ ] 全新目录克隆/解压后，`npm install && npm run dev` 一条命令起得来，浏览器自动打开能看到屋子。
- [ ] 断网状态下重启一次，仍能完整运行（不请求任何外部地址，可开 DevTools Network 核对）。
- [ ] `npm run check` 全绿，无 skipped 用例。
- [ ] 仓库里没有提交 `runtime/`、`node_modules/`、`logs/`。
- [ ] README 写清：怎么跑、怎么验收、选了哪些技术方案及理由、已知限制。

## 1. M1 场景与相机

- [ ] 打开 5 秒内整屋可见，客厅、卧室、门洞都在画面内，无家具被裁切。
- [ ] 相机只停在 4 个 90° 方位，不会穿墙；缩放 2～3 档，最近能看清脸部色块。
- [ ] 门洞是真实开洞（从客厅能看见卧室地面），不是贴图。
- [ ] 改 `furniture.json` 里沙发的 `position` 后重启，沙发位置真的变了。
- [ ] 在 `rooms.json` 加一个房间条目，场景多出房间，启动不报错。

## 2. M2 角色与走位

- [ ] 角色比例接近三头身，与三视图并排截图对比，发型/配色/服装一致。
- [ ] 从客厅任意点走到卧室床边：路径连续、不穿墙、不穿沙发，转身朝向前进方向。
- [ ] 走到椅子前会先停住、转身、再坐下，不是滑进椅子。
- [ ] 寻路遇阻挡时会绕行；无解时原地停下并在日志里留警告。

## 3. M3 导演与状态

- [ ] `state.json` 手工改 `write_notes`，5 秒内她走向电脑桌、坐下、翻本子、低头写。
- [ ] 模拟器点「沙发看电视」，10 秒内点「写笔记」：先走完看电视的最短停留，再起身走过去，无瞬移、无闪烁。
- [ ] 同一状态连写 10 次，动作不重启、画面不抖。
- [ ] 某次任务只持续 3 秒，她仍把那一套动作演完（`state-history.jsonl` 里 `prev_duration` > 任务时长）。
- [ ] POST 非法 `activity` 返回 400 且带 `allowed` 列表，前端不受影响。
- [ ] 请求体超过 8KB 返回 413。

## 4. M4 空闲池

- [ ] 静置 5 分钟内至少换过一次活动，顺序不固定。
- [ ] 静置 20 分钟，日志里出现 ≥ 3 种活动，且有权重差异（不是平均分布）。
- [ ] 23:30 之后（或临时把 `quiet_hours` 改成当前时间段），空闲池切到睡眠为主。
- [ ] 空闲时写入任务状态，能在最短停留后打断空闲行为。

## 5. M5 家具拖动

- [ ] 双击沙发高亮，拖动到另一角，松手后她下一次看电视走到新位置，准确坐下。
- [ ] 拖动电脑桌时她正在用电脑：她做完手上的动作再起身走向新位置，不留在空气里。
- [ ] 电脑桌与椅子联动移动（`group` 生效）。
- [ ] `Ctrl+Z` 撤销一步；刷新页面后布局保持；「恢复默认」能回到配置初始位置。
- [ ] 拖动时角色不会穿进被拖动的家具（或在拖动暂停路径并重算）。

## 6. M6 状态模拟器

- [ ] 双击 exe（或打包产物）启动，无需浏览器即可操作。
- [ ] 点「写笔记」3 秒内浏览器角色响应；点「停下」她回到空闲并进入空闲池。
- [ ] 模拟器窗口显示当前状态、来源、开始时间、最近 20 条历史。
- [ ] 浏览器关掉再开，模拟器仍可用，状态继续生效。
- [ ] 端口被占用时自动顺延并给出可读提示，模拟器能手填端口。

## 7. 自动与演示

- [ ] `npm run demo` 60 秒内依次触发六种活动并拖动一次沙发，全程无报错。
- [ ] `npm run check` 覆盖：配置合法性、状态接口错误、导演状态机、日志落盘，四项都有真实断言。
- [ ] 连续运行 2 小时，帧率下降 < 20%，内存无持续增长。

## 8. 扩展性（客户特别关注）

- [ ] `characters.json` 里把 `active` 换成 `shuaishuai`（占位形象），场景显示占位小人、不报错。
- [ ] 新增一个活动（如 `cooking`）只需加 `activities.json` 条目与一个交互点即可演出；如需改代码，README 里写明原因。
- [ ] 导演接口是 `setState(characterId, state)`，v0.1 内部路由给 active 角色。

## 9. 交付验收（客户亲自看）

- [ ] 演示：进屋 → 看她自己生活 → 拖动沙发 → 点模拟器 → 走出门洞去卧室睡觉。
- [ ] 客户提出的所有「待定问题」都有结论或被明确延期，写在 `docs/验收问题.md`。
