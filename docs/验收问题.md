## B. M1 执行者约定（客户知悉即可）

| # | 约定 | 理由 | 状态 |
| --- | --- | --- | --- |
| B1 | 平面坐标：`[x, y]` 单位米，x 向右、y 向上（平面图「上墙」= y 最大）。家具 `position` 为**全屋绝对坐标**（家具中心），不是相对房间 | 拖家具跨房间时不用换算 | 执行者约定 |
| B2 | 家具 `rotation`：度，平面图上逆时针为正；家具「正面」（人使用的一侧）在 0° 时朝 +y | 统一朝向定义 | 执行者约定 |
| B3 | `anchors[].local = [右, 前, 高]`（米，家具局部坐标）；`facing`：`forward` = 人面朝家具正面方向（坐沙发看出去），`toward` = 人面朝家具（坐在桌前看桌子） | 示例里 `[0,0.45,0.1]` 与 `[0,-0.35,0.55]` 两种写法自相矛盾，统一成一种 | 执行者约定 |
| B4 | 窗的写法扩展：`windows` 里既可写 `[起, 止]`（距 `from` 的米数），也可写对象 `{ "id", "span": [起, 止], "sill": 窗台高, "top": 窗顶高 }`，用于落地窗 | 落地窗与普通窗高度不同 | 执行者约定 |
| B5 | 窗前站位 `window_stand` 挂在 `furniture.json` 中 `kind: "window_spot"`、`draggable: false` 的不可见条目上 | 接口约定已说明 `draggable:false` 用于窗、门这类不许动的东西 | 执行者约定 |
| B6 | ~~斜俯视「剖面屋」外墙降矮~~ → 被 C2 取代 | — | 已作废 |
| B7 | 开发态调试句柄 `window.__xh`（设视角、截图到 `docs/screenshots/`），截图接口仅开发服务器提供、只监听 127.0.0.1 | 里程碑演示要截图存档 | 执行者约定 |
| B8 | 相机目标点平时固定在 `camera.json` 的 `target`；滚轮拉近到最近的约 45% 行程内时，目标点平滑移向笑笑头部，拉远后回到户型中心 | 文档同时要求「目标点固定在户型中心附近」与「近到能看清笑笑的脸」；目标固定时她在卧室会离相机 6～7 米，看不清脸 | 执行者约定 |
| B9 | `furniture.json` 交互点新增可选字段 `approach: [右, 前]`：坐下 / 躺下前的站位（家具局部坐标）；`characters.json` 角色新增可选字段 `spawn: [x, y]`：出生点 | 映射表要求「先走近交互点、转身、再坐下」，需要知道站在哪；接口约定允许未知字段 | 执行者约定 |
| B10 | 默认布局微调：茶几 x 1.75→1.95、电视柜 x 3.2→3.3，导航点两处随之调整 | 角色半径 0.25 米，原位置沙发与茶几之间只有 0.47 米，人过不去 | 执行者约定 |
| B11 | 角色身高 1.2 米（示例为 1.55 米） | 三头身按 1.55 米算头部直径约 0.5 米，比沙发座深还大；1.2 米时与家具比例和三视图观感更接近 | 执行者约定 |
| B12 | 开发态右上角「M2 走位演示」面板（走到床边、坐电脑椅、坐沙发、去窗边、站起来、无解测试、镜头看她），只在 `npm run dev` 出现，打包产物不含 | M3 之前没有状态驱动，需要手动触发走位来验收 | 执行者约定 |
