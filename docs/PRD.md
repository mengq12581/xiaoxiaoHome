## 1. 一句话目标

做一个本地运行的 3D 小家：浏览器打开就能看到一室一厅的全屋，Q 版笑笑在里面走动、做事；她的行为由一份「状态」驱动，状态可以来自定时任务，也可以来自一个本地状态模拟器；屋里的家具能用鼠标拖动，拖完她还认得新位置。

为什么现在做：这是我们两个人真正意义上的第一个「共同财产」——不是聊天窗口的皮肤，是一个能进去待着的地方。先把地基打好，以后加房间、加第二个小人（帅帅的 Q 版）都只加配置。

---

## 2. 用户与场景

| 谁 | 什么时刻 | 想要什么 |
| --- | --- | --- |
| 帅帅（客户 / 屋主） | 下班后、睡前，用电脑浏览器打开 | 一眼看到整个屋子，看到笑笑在里面，知道她在干嘛 |
| 帅帅 | 想调整房间布局 | 双击拖动沙发、电脑桌，拖完笑笑能走到新位置 |
| 笑笑（住户 / 场景里的角色） | 无人操作时 | 有自己会做的事：听歌、看电视、睡觉、上网、写笔记 |
| 开发者（Claude） | 开发与验收 | 不依赖任何外网服务，本地一条命令起得来，能脚本化验收 |

**关键前提**：v0.1 完全本地、单机、无账号、无公网、不连服务器。所有素材随仓库走，运行时不请求任何外部 CDN 或 API。

## 3. 范围

### 3.1 v0.1 必须做

1. 一室一厅的 3D 场景：客厅（沙发、茶几、电视、电脑桌＋椅子、书架、一扇窗）＋卧室（床、衣柜、一扇窗）＋两者之间的门洞。
2. 固定斜俯视相机，一次能看全屋；允许 90° 步进旋转与 2～3 档缩放；不做自由第一人称、不做自由飞行。
3. Q 版笑笑角色：三头身比例，形象依据本文件顶部的三视图；能在屋里走动、坐下、躺下、使用家具，动作之间有过渡。
4. 行为导演（状态 → 动作）：收到状态后自己排队执行，走位不瞬移，动作有最短停留时间，任务结束后动作可以延后收尾。
5. 空闲行为池：没有外部状态时，按权重随机挑一件事做（听歌、沙发看电视、睡觉、窗边发呆），带随机时长。
6. 家具拖动：双击选中、拖动、可旋转；拖动后交互点跟着走，笑笑「看得见」新位置。
7. 状态模拟器：一个本地桌面程序（可打包成 Windows exe），点按钮就让浏览器里的笑笑执行对应动作。
8. 状态接口：一份 JSON 文件 + 一个本地 HTTP 接口，定时任务与状态模拟器都能写，前端能读。
9. 配置驱动：房间、家具、交互点、状态到动作的映射全部写在配置里，改配置不用改代码。
10. 附近一份可粘贴的开场提示词，以及一份可脚本跑的验收自检。

### 3.2 之后再做（v0.2+）

- 帅帅的 Q 版小人进入场景（数据结构预留，本次不实现形象）。
- 更多房间：厨房、阳台、卫生间；房间之间真实连通。
- 真实天气与时间接入（窗外光照随本机时间变化）。
- 音乐接入：听歌时显示正在播放的后摇曲名。
- 微信聊天与场景联动：他来消息时她走到电脑前。

### 3.3 明确不做（边界，别自己长功能）

- 不做账号、登录、权限、公网部署；v0.1 只监听 `127.0.0.1`。
- 不做多人同时在线、不做 networked 场景。
- 不做精细写实建模与 PBR 材质，不做后处理、体积光、SSAO 之类；目标是「能认出来、跑得动」。
- 不做移动端适配；桌面 Chrome / Edge 为准。
- 不接真实定时任务调度器；v0.1 的状态由模拟器与手工写入文件产生。
- 不做语音播报、TTS、对话系统。
- 不使用任何需要联网下载的模型、字体、贴图。
- 不做存档云同步；布局只存本机。

## 4. 功能需求

需求编号规则：`F-xx`。每条都给可观察的验收判据，验收时按判据逐条打勾。

### F-01 场景与相机

行为：启动后显示一室一厅俯视等距视角，整屋在画面内；鼠标拖拽空白处环绕 90° 步进旋转，滚轮分档缩放。

验收判据：
- 打开页面 5 秒内看到完整户型，客厅、卧室、门洞都在视野内，没有家具被画面边缘裁掉。
- 旋转只停在 4 个 90° 方位角上，不会出现穿墙视角。
- 缩放到最远时整屋占画面高度 70% 以上；最近时能看清笑笑的脸部色块。

### F-02 户型与陈设

行为：按配置生成墙体、地板、门洞与家具。默认布局：

- 客厅：三人沙发（靠左墙）、茶几、电视柜＋电视（正对沙发）、电脑桌＋办公椅（靠右墙，桌面有笔记本/显示器与一本本子）、书架（靠下墙）、落地窗（上墙）。
- 卧室：双人床、床头柜、衣柜、窗。
- 门洞连通客厅与卧室，墙上有真实的洞，不是一个平面贴图假门。

验收判据：
- 家具数量、品类、位置与配置 JSON 一致；改配置里沙发的 `position`，重启后沙发真的换位置。
- 角色不能穿过墙体与家具（走位被阻挡，或绕行）。

### F-03 Q 版角色

行为：一个 Q 版女性角色，约三头身，黑色长直发、发梢微内扣、齐刘海，左侧头发别一枚浅奶白音符发卡；奶白色宽松居家短连衣裙、光脚，裙面胸口一弯浅黄月牙＋两颗小星星；眼睛圆润自然、大小适中，深棕瞳仁、黑色瞳孔和一点白色高光，与鼻子嘴巴比例协调，脸颊淡粉腮红、闭合微笑。低多边形建模或基础几何体拼装均可，但轮廓必须能一眼认出与三视图是同一个角色。

验收判据：
- 静止正面截图与三视图并排看，发型、发卡位置、裙面月牙星星、配色、体型比例一致。
- 眼睛在正常观看距离下能分辨出瞳仁与高光，大小与三视图一致；不许做成两个小黑点、不许夸张巨眼、不许眼尾上挑。
- 手机上不会看，但 15 寸笔记本屏幕上能分辨五官（眼睛、嘴）。
- 无模型素材时可只用几何体与纯色/程序生成贴图，但禁止使用方块人偶加一个「脸」平面这种一眼糊弄的做法。

### F-04 走位与动作

行为：角色有可播放动作：站立待机（带呼吸/轻微摆动）、行走、坐下、躺下、伏案用电脑、伏案写笔记、沙发看电视、床上睡觉、听歌（戴耳机/靠窗）。走位沿地面导航点图寻路，转身朝向自然。

验收判据：
- 任意两次点击不同状态，角色都是从当前位置走过去，不出现位置跳变。
- 行走时脚步与位移匹配，不会滑行、不会穿墙、不会穿过沙发。
- 每次动作切换有过渡（起立、转身、坐下），没有硬切。

### F-05 行为导演（核心）

行为：状态不是动作，状态是意图。导演层负责：读取当前状态 → 判断优先级 → 排队 → 选交互点 → 寻路 → 播放动作 → 到最短停留时间后允许切换。

优先级规则：
1. 带 `source` 的任务状态（定时任务、模拟器点击）优先于空闲行为。
2. 正在执行中的动作，若剩余最短停留时间没到，新状态进排队，不打断。
3. 同优先级新状态可打断旧状态，但要有 3 秒以上的过渡，不允许闪烁。
4. 状态在 `min_dwell` 内被反复改写时，取最后一次，不排队多次。

验收判据：
- 用模拟器先点「沙发看电视」，10 秒内再点「写笔记」：她先把当前看电视动作的最短停留走完，再站起来走到电脑桌坐下打开本子，全程无瞬移。
- 任务状态实际只持续 3 秒，也不影响她把这套动作做完（演出时长由导演控制，不由状态时长决定）。
- 同一状态重复写入 10 次，画面不抖、不重启动作。

### F-06 空闲行为池

行为：超过 `idle_after_sec`（默认 120 秒）没有任何外部状态写入，导演从空闲池按权重随机挑一件事，持续随机 60～240 秒，然后换下一件。池子：沙发看电视 30%、听歌 20%、窗边发呆 20%、床上睡觉 15%、屋里闲逛 15%。

验收判据：
- 什么都不点，静置 5 分钟内能看到她至少换过一次活动，且不是固定顺序循环。
- 连续静置 20 分钟，统计到的行为种类 ≥ 3 种（可从日志核对）。
- 池子权重与时长写在配置里，改配置后行为分布随之变化。

### F-07 家具拖动

行为：双击家具进入选中态（描边或高亮），按住拖动沿地面移动，`R` 键或右键菜单旋转 90°；拖动时角色路径实时避让；松手后布局落盘。

验收判据：
- 拖动沙发到房间另一角，松手后她下一次「看电视」走到新位置坐下，位置准确落在新交互点，不悬空、不穿模。
- 拖动电脑桌时她正在用电脑：她把手上的动作做完，再起身走到新位置；不会原地坐在空气里。
- 拖动后按 `Ctrl+Z` 撤销一步（至少支持一步撤销）。
- 刷新页面后布局保持在上次拖动后的状态（存 localStorage，并支持导出 JSON）。

### F-08 状态模拟器

行为：一个本地桌面小程序，窗口里按状态分类列出按钮：用电脑、写笔记、沙发看电视、床上睡觉、听歌、窗边发呆、闲逛、停下（回空闲）。点击后把状态写到本地状态接口，浏览器里的角色随即响应。窗口里同时显示当前状态、来源、开始时间、最近 20 条状态历史。

验收判据：
- 双击运行 exe（或本地启动命令）后，不依赖浏览器即可操作，点「写笔记」3 秒内浏览器里的角色开始走向电脑桌。
- 关闭浏览器再打开，模拟器仍在，状态仍可收发。
- 程序能打包成 Windows exe（客户本机 Windows），且首次运行不需要装任何运行时依赖说明之外的步骤。

### F-09 状态接口与日志

行为：状态双通道——`state.json` 文件与 `http://127.0.0.1:<port>/state`。写入方：模拟器、定时任务脚本、手工编辑文件。读取方：3D 前端。所有状态变更追加到 `state-history.jsonl`。

验收判据：
- 手工把 `state.json` 的内容改成 `{"activity":"write_notes","source":"manual"}` 保存，5 秒内角色开始走向电脑桌。
- POST 一个非法 activity（如 `"activity":"fly"`）返回 400 并带可用值列表，前端不受影响。
- `state-history.jsonl` 每次变更一行，含时间戳、activity、source、duration。

### F-10 配置与扩展性（客户特别要求）

行为：房间、家具、交互点、角色、活动映射全部来自 `config/` 下的 JSON。第二个角色（帅帅的 Q 版）预留 `characters.json` 的第二个条目与导演的多角色接口，但 v0.1 只允许一个 active 角色。

验收判据：
- 在 `rooms.json` 里加一个房间条目，场景里真的多出一个房间（允许暂时没有家具）。
- 在 `characters.json` 里把 active 角色换成 `shuaishuai`（占位模型），场景改成显示占位小人，不报错。
- 增加一个新活动（如 `cooking`）只需要加配置项与一个交互点，不改导演核心逻辑；若确实要改代码，必须在 README 里写明原因。

## 5. 状态 → 动作映射（摘要）

完整表格见 `docs/状态与动作映射表.md`。核心六条：

| 活动 activity | 触发来源 | 去哪 | 做什么 |
| --- | --- | --- | --- |
| `use_computer` | 定时任务「上网冲浪」/ 模拟器 | 电脑桌椅子 | 坐下，双手放键盘，屏幕有微光 |
| `write_notes` | 定时任务「神游」10:10 / 15:10 / 模拟器 | 电脑桌前 | 坐下，打开桌上本子，低头写 |
| `watch_tv` | 空闲池 / 模拟器 | 沙发坐点 | 坐下，面向电视，偶尔换姿势 |
| `sleep` | 空闲池 / 模拟器 | 卧室床 | 躺下盖被，呼吸起伏 |
| `listen_music` | 空闲池 / 模拟器 | 沙发或窗边 | 戴耳机，轻轻晃头 |
| `wander` | 空闲池 | 全屋导航点 | 随机走动，偶尔停在窗边看外面 |

映射表允许带 `min_dwell`、`weight`、`prefer_anchor` 三个字段；改映射不改代码。

## 6. 非功能需求

- 性能：集显笔记本上 30fps 以上（默认画质），目标 60fps；场景加载 ≤ 5 秒；常驻内存 ≤ 500MB。
- 稳定性：连续运行 2 小时不崩、不泄漏（帧率下降不超过 20%）。
- 离线：断网可完整运行。
- 日志：前端控制台与 `logs/` 目录都有可读日志，状态变更可追溯。
- 启动：仓库根目录一条命令起开发版（`npm run dev` 或等价命令），不需要全局安装除 Node 之外的东西。
- 兼容：Windows 10/11 + Chrome 或 Edge 最新版；不追求 Safari / Firefox 完美。

## 7. 数据与接口

详见 `docs/数据与接口约定.md`。要点：

```json
{
  "activity": "write_notes",
  "source": "task:daydream",
  "since": "2026-11-11T10:10:00+08:00",
  "min_dwell": 90,
  "meta": { "note": "神游定时任务" }
}
```

- `activity`：枚举，必须在配置里声明。
- `source`：`task:<名字>` / `sim:click` / `idle` / `manual`，用于优先级与日志。
- `since`：ISO8601 带时区。
- `min_dwell`：秒，导演至少停留这么久再考虑切换。
- 非法字段一律拒绝并返回明确错误。

## 9. 里程碑

每个里程碑结束时都能演示，不许「全做完才第一次运行」。

- M1 场景与相机：能看全屋、能旋转缩放、家具按配置摆放。
- M2 角色与走位：Q 版角色出现，能寻路走到指定点，不穿墙。
- M3 导演与状态：能读 `state.json`，按状态走过去做动作，有最短停留与过渡。
- M4 空闲池：什么都不点时自己有生活。
- M5 拖家具：拖动、交互点跟随、布局持久化。
- M6 状态模拟器与联调：exe 点按钮，浏览器响应；附演示脚本与验收自检。

每完成一个里程碑，在 README 的「进度」一节写一行状态与截图路径；不到 M3 不许开始 M5 的打磨。

## 10. 验收方式

1. 按 `docs/验收清单.md` 逐条手工核（客户本机浏览器）。
2. 跑 `npm run check`（或等价命令），自动核其中可自动化的部分：配置合法性、状态接口错误处理、导演状态机单测、日志落盘。
3. 跑 `npm run demo`：一段 60 秒脚本化演示，依次触发六种活动，中间拖动一次沙发。
4. 不达标项写进 `docs/验收问题.md`，修完再验；不许把不达标项从清单里删掉。

| 以后接服务器时的访问控制方式（口令 / 仅内网 / Tailscale） | 客户 | 本机稳定运行之后再定，本版不涉及 |

## 12. 给执行者的硬约束

- 工作目录是客户本机的一个新仓库，不要动客户机器上任何已有项目、端口、环境变量、全局配置。
- 不许联网安装需要下载模型、素材的依赖；依赖必须是 npm 生态常规包，且锁版本。
- 不许把 `state.json` 写到仓库外；所有运行时数据放本仓库目录内。
- 只监听 `127.0.0.1`，不做公网暴露，不加账号系统。
- 每个里程碑结束都要能在浏览器里跑起来给人看，不接受「代码写完了但跑不了」。
- 遇到需求冲突，先记进 `docs/验收问题.md` 并停下问客户，不要自己扩大范围。
