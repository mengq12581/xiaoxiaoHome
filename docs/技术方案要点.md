# 技术方案要点

本文件给执行者提供「给定事实」与「方案空间」，不代替 PRD 的验收判据。发生冲突时以 PRD 为准。

## 1. 给定事实

- 客户用 Windows 10/11 笔记本，浏览器为 Chrome 或 Edge；开发与验收都在他本机完成，不连服务器、不部署公网。
- 本机可安装 Node.js（LTS 20 或 22），这是唯一允许要求用户安装的开发依赖。
- 断网也要能跑：素材、字体、模型全部随仓库；禁止运行时请求 CDN。
- 没有现成的角色模型文件，唯一形象依据是 `assets/xiaoxiao_q_turnaround.jpg`（Q 版三视图，正面/侧面/背面）。
- 时间只有一种真实来源：运行时的系统时钟；`since` 由写入方给，前端不要自己编时间。
- 客户的机器上已有自己的项目与服务，新仓库请放在一个全新的空目录，不要碰别人东西。

## 2. 方案空间（执行者可自选，选完在 README 写清理由）

| 关注点 | 可行选项 | 建议 |
| --- | --- | --- |
| 渲染 | three.js（原生）、React Three Fiber、Babylon.js、PlayCanvas | three.js 原生或 R3F，生态与社区最大，问题好查 |
| 语言/工程 | TypeScript + Vite | 强烈建议 TS：导演层是状态机，类型能省一半调试 |
| 状态服务 | Node + express / fastify / 原生 http | 原生 http 足够，少一个依赖 |
| 模拟器 | Electron（复用前端 TS）、Tauri（体积小）、C# WinForms（客户本行） | Electron：与前端同栈，打包 Windows exe 最稳；体积大是唯一代价 |
| 寻路 | 网格 A*、导航点图 + Dijkstra、navmesh | 导航点图先跑通，天然满足「加房间只加配置」 |
| 动画 | 程序化骨骼/关键帧（代码插值）、简单 GLTF 自制骨骼、CSS sprite 伪装 | 程序化骨骼 + 关键姿势插值，避免依赖外部模型 |

## 3. 角色实现建议（最容易翻车的一环）

三选一，按可行性排序：

1. **程序化 Q 版骨骼模型**：胶囊躯干 + 球头 + 发片 + 四肢圆柱，用简单骨骼（头、颈、肩、肘、胯、膝）驱动关键姿势（站、坐、躺、走、写、看），姿势间用缓动插值。优点：零外部素材、动作可控、轮廓可直接照三视图定；缺点：脸部要靠贴图或色块，别做太复杂。
2. **低模 GLTF 自制**：用 Blender 之类做一版低模（若执行者环境有），导出 GLTF 与 8～10 个动画片段。缺点：需要美术判断，容易做成「方块人」。
3. **3D 场景 + 2D 精灵**（伪 3D）：角色是始终朝向相机的三视图裁切精灵，分视角切图。缺点：走动转向会穿帮，只在时间极紧时用。

不论哪种，判定标准只有一个：正面截图与三视图并排，客户一眼认得出是同一个人。

## 4. 导演层设计要点（核心，别做省略）

- 用一个显式状态机：`IDLE → MOVING → ACTING → (排队/回落) → IDLE`，状态迁移写日志。
- 队列最多 1 条：新状态覆盖排队项，`min_dwell` 未到就替换而不是堆叠。
- 「演出时长」独立于「状态时长」：`ACTING` 至少走完 `min_dwell`，状态早结束也不打断；这是客户最在意的观感。
- 过渡用 tween（位置、朝向、关节角度），所有切换有 0.4～1.2 秒缓冲；禁止 `position.set()` 直接跳。
- 拖动家具时：如果角色正在使用该家具，标记 `pendingRelocate`，动作结束后重算路径；如果没在使用，只更新交互点。
- 空闲池用加权随机 + 冷却（同一活动 90 秒内不重复）。

## 5. 路径与碰撞

- 地面导航点图由配置给出（`rooms.json` 的 `nav`），执行者可另加自动网格作为补全。
- 家具占位用 2D 矩形（`size` 的前两维）参与避让，拖动后实时更新。
- 角色半径 0.25m；墙角留 0.3m 余量。
- 寻路失败：原地停 + 警告日志 + 回落到 `idle_stand`，不许穿墙修复。

## 6. 性能预算

- 三角面 ≤ 15 万，材质 ≤ 40，纹理 ≤ 8 张 2K；阴影只用一张主光。
- 帧率：集显 30fps 起步；掉帧时优先降低阴影分辨率与像素比。
- 场景加载 ≤ 5 秒：模型/贴图一次性预热，不做运行中动态加载。

## 7. 开发与验收脚手架

- `npm run dev`：并行起状态服务（4317）与前端（5173），前端代理 `/state` 到服务端。
- `npm run sim`：起模拟器（Electron 开发态）。
- `npm run build:sim`：打出 Windows exe。
- `npm run check`：配置校验 + 接口错误处理 + 导演状态机单测 + 日志落盘检查，全绿才算过。
- `npm run demo`：脚本化演示（六种活动 + 拖一次沙发），用于里程碑演示。

## 8. 建议的推进顺序（每步都可演示）

1. 仓库骨架、Vite + TS、一个空房间 + 轨道相机（M1 前半）。
2. 户型与家具从 JSON 生成、门洞真实连通、相机 90° 步进与缩放（M1 后半）。
3. 角色模型（先静态站姿，能放屋里、比例对）（M2 前半）。
4. 导航点图 + A* + 走路动画 + 转向（M2 后半）。
5. 状态服务 + 文件通道 + 导演状态机 + 两种活动（M3）。
6. 六种活动动画与道具、最短停留、过渡打磨（M3 后半）。
7. 空闲池权重与随机时长、静默回落（M4）。
8. 家具选中、拖动、旋转、联动组、撤销、布局持久化（M5）。
9. 交互点跟随 + 使用中拖动策略（M5 后半）。
10. 模拟器界面、打包 exe、与浏览器联调（M6）。
11. `npm run check` / `npm run demo`、README、验收清单逐条过（M6 后半）。

## 9. 风险清单

| 风险 | 表现 | 对策 |
| --- | --- | --- |
| Q 版角色做不像 | 方块人、脸糊 | 先把静态站姿对照三视图定比例，再谈动画 |
| 动作太硬 | 坐下像瞬移 | 所有切换走 tween，过渡时间写进配置 |
| 穿墙 | 家具拖动后路径没更新 | 交互点连云节点，路径每次现算，不留缓存 |
| 导演抖动 | 重复状态导致动作重启 | 相同 activity + 相同 source 视为幂等，不重启 |
| 模拟器与前端端口打架 | 连不上 | 端口自动顺延并打印，模拟器允许手填端口 |
| 依赖联网 | 断网跑不起来 | 所有依赖 `package-lock.json` 锁定，构建不下载资源 |

## 10. 不许做的实现取巧

- 不许用「贴图假门」「平面假窗」代替有厚度的墙体开洞。
- 不许用 CSS 动画冒充 3D 走位（角色必须真的在场景坐标系里移动）。
- 不许把状态写在 localStorage 冒充服务端状态。
- 不许跳过 `min_dwell` 直接把任务时长当演出时长。
- 不许把「不做清单」里的功能顺手实现——出现了就是范围失控。
